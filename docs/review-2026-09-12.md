# Review, 2026-09-12: findings and what changed

The tool was put through an adversarial review with one instruction above all
others: **make it report PASS on a change that would break a real consumer.**
A gate that fails when it should not is annoying. A gate that passes when it
should not is worse than no gate, because it is trusted.

It found two ways to do that. Both are fixed, and both now have a test that
fails if they come back.

The review prompt itself is reusable and lives outside this repository; the
findings below are reproduced in full, including the ones that were not fixed.

---

## BLOCKER: differential mode reported PASS on a status-code change

**Reproduced:** two services returning an identical body, baseline `201`,
candidate `200`.

```
drifts:      []
differences: []
checks:      []
VERDICT:     PASS
```

The status of each side was captured in the evidence and never compared. A
check existed only when the case declared `expect_status`, that is, only when
someone had predicted that exact change, which is the work this tool exists to
make unnecessary.

Worse, the recorded-contract mode already did this correctly via
`recorded_status`. The mode presented as the most rigorous was the weaker one.

**Fixed:** `_status_parity_checks` compares the observed status sets of both
sides on every case. Pinned by
`test_a_status_divergence_fails_without_anyone_having_predicted_it`.

## BLOCKER: an empty collection read as five breaking changes

**Reproduced:** a contract recorded on a day the catalogue had rows, run on a
day the filter matched nothing.

```
breaking FIELD_REMOVED $.products[]
breaking FIELD_REMOVED $.products[].id
breaking FIELD_REMOVED $.products[].price
breaking FIELD_REMOVED $.products[].tags
breaking FIELD_REMOVED $.products[].tags[]
```

The build fails because a search returned nothing. That is every endpoint with
a filter, a search or pagination past the last page, which is most of them. The first
time a nightly gate fails on a healthy service, somebody switches it off.

It also falsified a claim written in ADR-002: that a recorded contract "stays
valid until someone actually changes the API". It did not; it also failed when
the *data* went empty, which is the exact rot the ADR claimed to have removed.

The existing test `test_an_empty_array_does_not_look_like_a_removed_field`
passed throughout, because in it both sides had rows in some sample. It gave
false confidence on precisely this point.

**Fixed:** a collection that is empty on one side makes its item subtree
*unobserved*, which is a different fact from *absent*. Those paths are now
reported separately as "not checked": not a finding, and not silence either,
because a gate that quietly stops checking a subtree gives false confidence of
its own. Four tests pin it, including one that the fix must not become a
blanket amnesty for anything under an array.

## MAJOR: the retry default disabled the flagship feature

`max_retries` defaulted to `1`, with retries on `429` and `5xx`. An endpoint
failing one call in three was retried into a `200` before flakiness triage ever
saw it. The bundled demo had to set `max_retries = 0` with a comment explaining
why: the tool was disabling its own default to make its headline feature work.

**Fixed:** the default is now `0`, documented at the point of definition.

## MAJOR: redaction leaked common credentials and destroyed common QA data

Leaked into evidence: AWS **secret** access keys (only the `AKIA…` *id* was
matched), bare hex API keys, UUID session ids, Stripe `rk_live_…` keys.

Destroyed in evidence: EAN-13 barcodes, Brazilian phone numbers with a country
code, nanosecond timestamps, unpunctuated CNPJs, while a 23-digit order number
and a 44-digit NF-e key survived, because the card pattern stopped at 19 digits.
A rule that mangles a barcode produces evidence you cannot attach to the ticket
it was collected for.

**Fixed:** card masking is gated behind a Luhn checksum, which is what separates
a real PAN from a barcode. More prefixed shapes added (Stripe, GitLab, npm,
DigitalOcean). The module docstring and `SECURITY.md` now state the boundary
plainly instead of implying coverage the pattern list does not have.

## MAJOR: `pip install` produced a package that could not run its own demo

```
$ pip install .          # clean venv
$ parity-gate demo       # from any directory that is not a clone
demo suite not found at .../Lib/suites/demo-catalog.toml
```

**Fixed:** demo suites and their recorded contract live in
`src/parity_gate/demo/` and are resolved with `importlib.resources`, so they
ship in the wheel. `parity-gate demo --mode {differential,contract,stability}`
replaces asking people to type package-internal paths.

## MAJOR: strictly sequential, with no connection reuse

200 cases × 3 repeats × 2 sides = 1200 calls in series: one minute at 50 ms RTT,
eight at 400 ms.

**Fixed.** Two halves.

`policy.workers` runs cases concurrently, defaulting to `1`
because a QA tool that quietly puts eight times the load on someone's staging
environment is a bad guest. Results are consumed in submission order, so a
parallel run produces the same report, the same hash chain and the same console
output as a sequential one, pinned by a test that diffs the two.

Connection reuse was initially declined: the module that would be rewritten is
also the one performing redirect re-validation, and that is the most
safety-critical code here. It was then done anyway, on `http.client` with a
per-host pool, and the trade turned out to be the other way round: writing the
redirect loop explicitly makes the security property *more* visible than
inheriting `urllib`'s handler chain, and it surfaced a gap that inheritance had
hidden: credentials were being replayed across a host change. They are now
stripped.

Measured against a live HTTPS API, same network, same minute:

```
12 calls, connection reused : 0.20s   (16 ms/call)
12 calls, fresh socket each : 1.25s  (104 ms/call)   <- what it did before
```

The demo's 36 requests now go over one TCP connection, asserted by counting
sockets at the server. Sixteen tests cover the module, including a redirect to
a host outside the allow-list (refused before the packet), a redirect loop, the
303-degrades-to-GET rule, and recovery from a connection the peer had closed,
retried only for methods that can safely be repeated.

## MAJOR: identity matching fell back to positional in silence

Asking for `"$.products" = "id"` and getting a positional comparison, with no
signal, means the resulting noise gets blamed on the API rather than on the
configuration.

**Fixed:** emits a `KEY_MATCH_UNAVAILABLE` finding naming the key and what
happened instead.

## MINOR: three smaller things

- **`preflight` did not resolve credentials**, so a missing environment variable
  surfaced mid-run rather than as a refusal at the door. Fixed.
- **Contract mode printed "0 value diff"**, which reads as "no values changed"
  rather than "values were not checked". It now says the latter.
- **The README claimed a CI matrix that had never executed.** The claim is now
  what is actually true.

## MINOR: the secret scanner flagged its own documentation

Found by running `parity-gate scan` across this repository while wiring it into
CI, which, since CI had never executed, had never actually been tried.

```
README.md:289: looks like a live http-auth
```

Line 289 reads *"an integration test asserts a token supplied through the
environment never leaks"*. The pattern matched the English word **token**
followed by any eight characters. Every test fixture holding a deliberately
fake credential was flagged too.

Both halves matter. A scanner with no way to say "this one is a fixture" gets
excluded from the directory it was pointed at, and a scanner that flags prose
gets ignored, and an ignored scanner is indistinguishable from no scanner.

**Fixed:** the value after `Bearer`/`Basic`/`Token` now has to contain a digit,
or be a long unbroken run of letters, before it counts. Files and lines that
legitimately contain credential-shaped strings carry an explicit
`parity-gate:allow-secrets-file` / `parity-gate:allow-secret` pragma, so the
exemption is visible in the file rather than as a path missing from a CI
command. Pinned by `test_english_prose_about_tokens_is_not_a_finding`.

## What the review found to be sound

Worth recording, because a review that only lists problems is not a review.

**The evidence hash chain holds.** The attempt was to remove the record that
failed, relink the pointers, update `chain_head` *and* recompute the unsigned
manifest. It was still caught, because the following record's hash was computed
over the original link. `SECURITY.md` states the real limit (whoever can edit
the records can recompute the chain) rather than claiming cryptographic proof.

**Redirect re-validation is correct.** All five redirect statuses, 308 included,
route through `redirect_request`, so overriding that one method covers every
hop rather than the two or three a per-status implementation would have caught.

**The noise engineering is the real contribution and it works.** Masking with
automatic suggestion, identity matching, folding findings that restate a drift,
and refusing to diff an unstable endpoint are what separate this from a deep
JSON diff with a CLI.

## Second pass: using it as a stranger would

The repository was then cloned fresh and pointed at a public API that had
nothing to do with this project, following the README as written. Three more
things came out of that.

**A credential was masked even when there was none.** Evidence reported
`"authorization": "[REDACTED]"` for a request that had sent no credential,
because a sensitive *key* was masked regardless of its value. Masking `null`
protects nothing and destroys the only thing a reader needs: whether the
header went out at all. Empty values under sensitive keys are now left visible.

Found by writing the end-to-end auth test that did not exist: `resolved_headers`
was unit-tested, but nothing asserted the header actually reached a server. The
mock now echoes it back, so one run proves both that it arrived and that it is
gone from the bundle written afterwards.

**No way to run a subset.** A two-hundred-case suite with one failing endpoint
was all or nothing. `--filter` takes a glob against a case id or requirement, or
a substring of a title, and says which cases exist when nothing matches.

**Evidence grew without bound**: one directory per run, forever. `--keep N`
prunes, off by default, and only ever touches directories that carry a manifest,
so an evidence folder somebody also keeps notes in does not lose them.

## Third pass: the protocols and tools it did not serve

An honest limits section named four reasons someone would put this down:
GraphQL, gRPC, streaming, and "I already have an OpenAPI spec". Two of them
turned out to be a decision rather than a constraint.

**GraphQL was never a protocol problem.** It is JSON over HTTP and the contract
engine applied unchanged. What did not apply was everything inferred from the
*method* and the *status*: every operation is a POST, so the write gate would
have forced every query to be declared a mutation; and every response is 200,
so the check that catches a softened error had nothing to read. Both now come
from the query document and the `errors` array instead. Supported, with
subscriptions refused at load time and told why.

**An OpenAPI spec was being treated as a reason not to use the tool.** It is a
reason to use a different one *for a different question*. Schemathesis checks
the code against the spec, this checks the code against yesterday. But the spec
also lists the endpoints, and typing that list into TOML was the single largest
piece of adoption friction. `import-openapi` removes it, and commented-out
cases mark every path parameter it could not fill rather than inventing one.

**gRPC and long-lived streams stay out**, and the README now says who to use
instead (`buf breaking`, `Protolock`) rather than listing them as a gap. A
breaking-change check for a schema-first protocol belongs in that protocol's
toolchain; adding protobuf to a zero-dependency tool to do it worse would be a
claim, not a feature.

## Still open

- Stability is sampled three times back to back, which structurally cannot see
  flakiness on a slower period than that.
- Redaction remains pattern-based, and a naked high-entropy value under an
  innocuous key is not caught. Stated in `SECURITY.md` rather than papered over.
