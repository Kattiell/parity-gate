# Review, 2026-09-13: what was claimed, what was measured

The first review asked the tool to report PASS on a breaking change. This one
asked two different questions. Is everything the repository says about itself
actually executed somewhere? And can the gate's detection be *measured*,
continuously, instead of argued once?

Both turned something up.

---

## BLOCKER: the CI the README described had never existed

The README carried a CI badge. SECURITY.md said the tool scans its own
repository "on every build". The previous review recorded "the README claimed a
CI matrix that had never executed" as fixed. There was no workflow file in the
repository, and GitHub showed zero workflow runs.

For a project whose argument is that its claims are checked, that was the most
expensive gap in it, and the previous review made it worse by marking it closed.
That entry now carries a correction pointing here.

**Fixed:** `.github/workflows/ci.yml` runs, with `contents: read` and no
secrets: ruff, format, mypy, the credential scan, `verify` on the committed
evidence, the selftest, the test suite on Python 3.11 to 3.13 on Linux and
Windows, and the contract demo asserting it exits `2`. If a claim is not a step
in that file, the README no longer makes it.

## MAJOR: a trickled body could hold a run open indefinitely

`timeout_seconds` was a socket timeout, and a socket timeout is reset by every
byte that arrives. A server sending one byte every few seconds never timed out.
In CI that is a job that runs until the platform kills it, with no evidence.

**Fixed:** it is now a deadline for the whole body. The body is read with
`read1`, at most one socket read at a time, and the socket timeout is shrunk to
what is left of the deadline before each one. Pinned by a test that trickles a
body at one byte per 50 ms against a one-second deadline.

## MAJOR: a response body had no size limit

`raw_response.read()` loaded whatever came back. An export endpoint listed in a
suite by mistake could exhaust the runner's memory.

**Fixed:** `policy.max_response_bytes` (10 MiB). A declared oversize is refused
before reading; an undeclared one is cut off at the cap. Neither is retried on
the stale-connection path, because a body that was too big is as big again.

## MAJOR: deeply nested JSON ended the run with no evidence

A body nested 5000 levels deep made `json.loads` raise `RecursionError`, and only
`JSONDecodeError` was caught. The exception escaped the worker thread at
`future.result()` and took the whole run down: no report, and every finished case
discarded.

**Fixed, twice.** Nesting beyond 64 levels (the bound redaction already used) is
refused at decode time as a `json` finding about the response. And, as the general
form, any unexpected exception while judging a case becomes an `ERROR` record for
that case, located and redacted, while the other cases complete. The first time
that containment ran in development it caught a real refactoring mistake and
reported it as an `ERROR` record instead of a traceback.

## MAJOR: one item changing type passed with a warning

Found by the selftest described below, on its first run.

One product of four whose `price` comes back as a string makes the field's
observed types the union `{number, string}`. Nothing was removed from the union,
so it was classified `TYPE_WIDENED`, severity risky, and the case passed with a
warning, in both modes. That is how this defect actually ships (one row
serialised by a different code path), the README's own severity table calls
`number` to `string` breaking, and the consumer parsing that product fails
regardless of what the other three contain.

The selftest reported it as 19 missed faults in differential mode and 21 in
contract mode, every one of them this.

**Fixed:** a new type outside the numeric family is breaking. The exception is a
field the baseline only ever returned as null, whose type was never observed;
a first real value there stays risky. After the fix: 187 of 187 and 137 of 137
faults detected, no false alarms. Pinned in `test_schema.py`.

## Added

**`parity-gate selftest`.** Diagnostic coverage for the gate: a fixed fault model
(type change, null, missing field, changed status; changed value, dropped item and
empty page in differential mode) is injected into real responses one site at a
time, and a set of controls the gate must tolerate measures false alarms. Mutants
go through `judge_differential` and `judge_contract`, the same functions a real
run uses, which required separating judging from I/O in `runner.py`. Its own tests
break the gate on purpose and assert the score drops.

**Rule ids and SARIF.** Every finding carries a stable id from a pinned catalogue
(`docs/rules.md`). Every bundle includes `report.sarif`, with contract drift located
on the field's own line in the recorded contract and fingerprints that let an
alert be tracked across runs.

**Waivers.** `[[waivers]]` in a suite accept a finding with an owner, a reason and
an expiry the gate enforces. A waived finding stays in every report and turns a
failure into a warning; a lapsed waiver waives nothing; an unused one is listed.
The test strategy already asked for "a named owner per warning"; now there is a
place to write it that the gate reads.

**`parity-gate history`.** The previous review left "stability is sampled back to
back" open. Every run now records the revision under test, and `history` reads the
verified bundles in a directory and classifies each case as intermittent,
regressed, recovered or steady. Two outcomes on one revision is intermittent even
with a single flip. `policy.repeat_interval_ms` spaces samples within a run.

**House style.** Em dashes were removed from the prose, the code and the reports
the tool writes, and a test keeps them out. The sample bundle in `docs/evidence`
was regenerated rather than edited, since it is hashed in its own manifest.

## Still open

- **Headers can still be trickled.** The status line and headers are read by
  `http.client` under the per-read timeout and its own header limits, not under
  the body deadline. Stated in SECURITY.md.
- **The evidence chain is not a signature.** Whoever can edit the records can
  recompute it. Signing the manifest in CI (an artifact attestation, for
  instance) would close that for bundles produced there; it is not done.
- **Enumerations are not part of the contract.** A string field whose set of
  values grows is invisible to a shape-only contract, and a strict consumer can
  break on it. Recording value sets would need an opt-in that respects ADR-002.
- **Latency is a median of a few samples**, the first of which pays for the
  connection, and differential mode does not compare the two sides' latency.
- **The selftest's 100% is over a fixed model**, and `history` only sees as far
  back as the bundles kept.
- **Commit messages before this pass still contain em dashes.** Rewriting pushed
  history would need a force-push to `main`, so they were left as they are.
